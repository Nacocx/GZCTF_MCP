日期：2026-10-21。范围：审查 A1–A7、A9–A10；保留并回归 A8 的已完成代理集成。仅本地 Docker 验证，不操作用户远端站点。

## 阶段与验收

1. P1 正确性与兼容性：相同附件跳过重复绑定、恢复后内容校验；显式截止清空及带时区输入；计分有限正数；结构化脱敏业务错误；官方 X25519/SHA256/AES-GCM 加密、Cookie 格式识别、公开配置/认证诊断、环境账密登录/登出及验证码状态。先通过定向回归再进入 P2。
2. P2 平台流程：分组 CRUD 与命名权限位、单题权限、按组名称准确报名与最终参与状态、报名查询/审核；比赛完整读改写/删除、三血参数、海报公告、文件清理；队伍创建/修改/邀请/退出、退赛、Writeup 状态；赛务事件/提交/实例清单与停止。通过接口契约检查后进入 P3。
3. P3 批量与二进制：比赛 ZIP 导入导出、榜单/提交/Writeup 导出；多清单预演、执行计划、原子本地进度保存、按明确 ID 恢复、禁止不确定创建自动重试；动态附件每 Flag 本地路径自动上传。增加本地真实加密、分组、审核、截止清空、附件恢复、批量/导出与管理验证。记录未验证的外部服务边界。

## 约束

- Python 用项目 conda；保留用户 .env、上游源码、当前功能分支，不推送。
- 账密仅环境输入，验证码遵守原站策略（支持用户提供校验结果，不绕过验证码）；不自动重试提交、登录或其他写操作。
- 错误可保留经过脱敏及限长的业务 title/status，不输出请求秘密。
- 比赛 PUT 先读取原完整对象并合并显式字段，防止默认值覆盖无关设置。
- 本地执行状态不存 Cookie、密码或明文 Flag；权限/目标/输入指纹绑定，文件仅在工作区，写入原子并限制权限；遇到 creating 状态中断，先查唯一标识或要求显式 ID 不能盲目新建。
- 清理工具明确资源 ID，默认预演；不把共享文件引用减少当作源存储已删除，不对任意外站附件发送 Cookie。
