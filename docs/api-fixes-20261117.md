## 使用变化

- 新绑定不能仅传以前存下的 `fileHash`：先在当前 MCP 会话上传一次，或用 `attachmentPath`。一次上传只供一个新增消费者；相同题目恢复不重复消费。
- 单题调用的未使用上传引用只存内存。需要跨进程恢复时使用批量部署，账本记录引用对应位置。绑定失败时先核对实际状态，不能把不确定引用转给另一题。
- `admin_batch_reconcile` 支持 `reference_slot`，每次只核对一个记录位置；上传哈希参数改为单个 `[hash]`，或确认创建/确认上传未发生时的 `[]`。详见[使用说明](gap-remediation-usage.md)。
- 旧账本的已完成项继续跳过；只有 hash 计数、没有位置归属的旧未完成项不会被自动消费。
- 比赛更新锁作用于当前 MCP 客户端；网页或其他进程的同时编辑仍需协调。
