# API 核查修复规格

## 范围

落实 `api-review-20261117.md` 的 R1–R6，并补充工具字段单位、确定性预检及公告分页。保持既有工具名称，不扩展站点管理或 Passkey 功能。

## 设计

- 本地附件新绑定必须消费一次已确认的上传引用；同一 MCP 进程通过 `admin_upload_file` 上传的引用按次数消费。旧 hash 本身不证明有可消费引用，进程重启后需重新上传或使用附件路径。相同目标的相同附件恢复只读验证，不重新消费。
- 批量部署将上传记录绑定到公共附件或 Flag 索引，保存上传、绑定中和绑定完成状态；恢复不得将已绑定引用借给另一位置。不确定上传/绑定保留核对入口，旧账本不能自动把无归属 hash 当作可用引用。
- JSON 与流式 HTTP 统一处理 Cookie 续期和网络异常；错误保留 HTTP 状态供恢复逻辑判断。公开附件默认匿名下载，可显式指定角色。
- 同一客户端按比赛 ID 锁定完整读改写，读回核对本次 patch；不自动重试写请求。
- 清理持久化 deleting 状态；恢复先确认管理员可访问比赛与题目列表，仅对已记录 deleting 且确认不存在的题目收敛账本。
- 为 CPU、容量、时间、截止清空等字段提供 Schema 描述；预演拒绝空白文件名和非容器流量捕获。

## 验收

使用现有 conda 环境，定向覆盖引用消费/恢复、读回超时、并发修改、Cookie 续期、删除响应丢失和匿名下载。只执行相关测试与静态检查，不访问用户真实业务站点。更新 changelog 和使用说明；审查原始证据保留为修复前快照。
